# split-tunnel-apps

Автоматически обновляемые списки Android-приложений для раздельного туннелирования.

- `public/direct_apps.txt` — приложения, для которых есть явное свидетельство конфликта с включенным VPN.
- `public/proxy_apps.txt` — приложения, для которых есть явное свидетельство необходимости VPN для доступа или нормальной работы.

Парсеры ищут в отзывах только упоминания `VPN`, `ВПН` и `КВН`. Из отзыва извлекается только предложение с таким упоминанием; если оно слишком длинное или без нормальной пунктуации, используется окно до 10 слов слева и справа. Полные отзывы и промежуточные результаты в репозитории не сохраняются.

Фрагменты одного пользовательского отзыва и ответ разработчика к нему остаются одним независимым `report`. DeepSeek получает до нескольких таких report на приложение и возвращает `DIRECT`, `PROXY` или внутренний `SKIP`.

Критерий намеренно консервативный: одиночные и даже два обычных пользовательских сообщения о сетевой проблеме не считаются общим правилом маршрутизации. Для таких случаев нужны минимум три независимых подтверждения. Одного сообщения достаточно только для прямого app-level запрета VPN/подтверждения разработчика или явного общего ограничения сервиса для пользователей в России. При сомнении используется `SKIP`, который не публикуется.

Каждый запуск заново строит модельную часть DIRECT/PROXY. Старые модельные решения не переносятся автоматически. В коде остается только маленький набор независимо проверенных маршрутов, чтобы очевидно подтвержденные приложения не исчезали из-за окна свежих отзывов.

Для ранее опубликованных package ID проверяется более глубокая выборка отзывов, чем для новых кандидатов. При ошибке DeepSeek публикация прерывается целиком, чтобы не сохранить частичный результат.

Для GitHub Actions требуется Repository Secret `DEEPSEEK_API_KEY`. Модель можно переопределить Repository Variable `DEEPSEEK_MODEL`; по умолчанию используется `deepseek-chat`.
